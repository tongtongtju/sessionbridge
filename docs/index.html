// Two directions

One plugin,
both ways

Whether you're moving from Codex to Claude Code or vice versa, sessionbridge handles the format conversion automatically.

cx2cl — codex to claude

Codex → Claude Code

Continue your Codex development in Claude Code. Injects context into the current conversation or creates a full JSONL session file with DAG chains and tool call mapping.

# Inject into current session /sessionbridge:import-session cx2cl 019e733c...
# Create new session file /sessionbridge:import-session cx2cl 019e733c... --new-session
cl2cx — claude to codex

Claude Code → Codex

Export your Claude Code session to Codex format. Generates proper Codex JSONL with session_meta, turn_context, event_msg, and registers in the SQLite index.

# Create new Codex session /sessionbridge:import-session cl2cx 513fbe94...
# Inject summary into current conversation /sessionbridge:import-session cl2cx 513fbe94... --inject

// How it works

Three steps,
either direction

01

Load the plugin

Start Claude Code in your project directory with the plugin loaded.

cd /path/to/your-project claude --plugin-dir /path/to/sessionbridge
02

Find your session

List sessions from either tool. The plugin queries SQLite databases and scans filesystem.

# List Codex sessions /sessionbridge:import-session cx2cl --list # List Claude sessions /sessionbridge:import-session cl2cx --list
03

Migrate and continue

Pass the session ID. Choose inject mode (default for cx2cl) or file creation mode.

# Codex → Claude (inject into current session) /sessionbridge:import-session cx2cl 019e733c... # Claude → Codex (create new session) /sessionbridge:import-session cl2cx 513fbe94...

// Architecture

Under the hood

How sessionbridge converts between two entirely different session formats — Codex's SQLite-indexed JSONL and Claude Code's DAG-linked conversation records.

┌────────────────────────────────────────────────────────────────────────────┐ │ sessionbridge │ │ │ │ Direction 1: cx2cl (Codex → Claude) │ │ │ │ codex-parser ──parse──→ ParsedSession ──write──→ claude-writer │ │ │ (IR) │ │ │ ▼ ▼ │ │ Codex JSONL context-builder Claude JSONL │ │ (inject mode) + DAG chains │ │ │ │ Direction 2: cl2cx (Claude → Codex) │ │ │ │ claude-reader ──parse──→ ParsedSession ──write──→ codex-writer │ │ │ (IR) │ │ │ ▼ ▼ │ │ Claude JSONL context-builder Codex JSONL │ │ + tool_use pairs (--inject) + SQLite index │ └────────────────────────────────────────────────────────────────────────────┘
⊞

Codex Format

JSONL indexed by SQLite. Records: session_meta, turn_context, event_msg, response_item. UUID v7 session IDs. Tools: exec_command, apply_patch.

⊡

Claude Code Format

JSONL with DAG-linked records (uuid + parentUuid). Types: user, assistant, tool_result. UUID v4 session IDs. Tools: Bash, Edit, Read.

// FAQ

Common questions

Where does session data live?
Codex: ~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl indexed by ~/.codex/state_5.sqlite.
Claude Code: ~/.claude/projects/<slug>/<uuid>.jsonl (pure file, no SQLite).
Will it modify my original sessions?
No. All operations are strictly read-only on source data. Converted files are written to the target directory.
What data is preserved vs. lost?
Preserved: User messages, assistant replies, tool calls and results, file changes, timestamps, git branch.
Lost: Encrypted reasoning content, web search results, sub-agent structures, hook progress records.
Do I need both Codex and Claude Code installed?
You only need Claude Code to run the plugin. Codex sessions are read directly from disk — you don't need Codex CLI installed or running.
Inject mode or new session — which should I use?
Inject for quick context handoff in your current conversation.
New session for a fully independent, resumable session with complete history.
